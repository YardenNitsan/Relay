# Grouped Settings

Continue the approved Studio design with one readable settings document. Personal appearance and task notifications sit alongside connections on desktop; phones use a single scrollable column with comfortable controls. Account and execution-host identity remain explicit. Use existing semantic tokens, native controls and modular feature views.

Settings is a navigation and preference surface, not a second configuration system. Reuse the current theme preference, notification controller, Google Workspace, model connections, client grants, Memory and owner-only Host/Access/MCP/Schedules destinations. Keep existing direct navigation and commands. Do not fetch credentials or load models to render Settings. A shared account must never receive owner-only management links.

Verify opening from phone navigation and command palette, real destination handoff, draft preservation, theme persistence, inaccessible-owner controls for a shared account, narrow/landscape layout and scoped accessibility. Notifications retain the browser-open limitation; no fake Companion/onboarding status or live-account claim.
