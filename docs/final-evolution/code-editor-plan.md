# Professional source editing

Scope B06/C03 and the owner's complete frontend directive. Current project authoring uses native textareas. Retain its exact-hash save, busy/draft guards, acknowledged mutations, explicit deletion and permission boundaries while adding an actual code editor for supported source files.

Use maintained CodeMirror6 modules, lazily loaded with Projects. Its modular editor is better suited to this bounded browser workspace than shipping a full IDE/Monaco service. Keep ordinary text in the existing native control. Detect mixed line endings and require an explicit normalization choice before code editing; do not claim the native textarea preserves mixed raw line endings after user input. Reading/downloading original content must remain available without conversion. Use the same edit/save authority for both representations, with honest language and line-ending labels. No LSP server, execution engine, alternate draft store or automatic source publication.

Target JavaScript/TypeScript, Python, C# and JSON: syntax highlighting, line numbers, current position, undo/redo, literal search and optional wrapping. Preserve exact LF/CRLF text and final newline. Do not capture Tab as indentation by default; retain keyboard escape and native modal focus. Read-only state must refuse document changes independently of disabled toolbar controls. Busy save must also prevent editing. Use semantic theme tokens, comfortable phone controls and the existing visible-viewport/focused-editor layout. Actual Android IME and screen-reader acceptance remains separate.
