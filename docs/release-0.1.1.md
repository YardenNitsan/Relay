# Relay 0.1.1 — shared host update

9 October 2026. This is the current implementation report; older sections of the project report and validation ledger preserve earlier snapshots, not the current deployment state.

## 10 October follow-up: LM Studio execution

Relay now combines downloaded chat catalogs from Ollama and LM Studio. The host verified five Ollama and eight LM Studio chat models; an embedding-only model is excluded from chat. Desktop and phone discovery/selection passed. The official LM Studio SDK provides memory estimates and controlled loading for admitted models, with pinned context/concurrency/offload, live pressure cancellation, and cleanup limited to Relay's own instance. A real Qwen 3.5 9B conversation completed and persisted its final greeting; no private instance remained loaded afterward.

Auto and specialist routing include both authorized runtime pools, disclose coding-name heuristics, and reject speed evidence from incompatible context/offload configurations. A later Auto attempt correctly paused when a running game left RAM below the Safe reserve; no universal best-model or crash-proof claim is made. Automatic installed-service startup is loopback-only, with an opt-out and no interruption of an existing listener. True operation without the desktop app uses LM Studio's official llmster service.

The complete check passed 871 tests with one platform skip, followed by additional regressions and a final 117-test focused check. Uncertain SDK loading or cleanup blocks all local inference in the current Relay process; automatic startup requires llmster and never launches a desktop-only installation. The production build and real desktop/phone inspection passed. The official headless runtime was installed on this Windows host after checksum verification; cold startup confirmed `isDaemon:true`, loopback-only binding and all eight LM Studio chat models. See [current validation](validation.md) and [runtime setup, accounting and limitations](local-inference.md). Large models can still be rejected under current resource pressure; native Linux/macOS/Apple/AMD acceptance and artifact-bound LM Studio calibration remain unverified.

## Open Relay

- On the host: **http://127.0.0.1:4317**. Pair through the protected one-use code generated by `setup.cmd` or `npm run pair`.
- On another device for this deployment: **https://relay-host.yarden-relay.workers.dev**. Cloudflare Access sign-in and Relay account approval are required. The address remains unchanged by application updates.
- The PC and tunnel must be running. Local use survives an Internet/tunnel outage. Tunnel autostart is not yet installed as a native service.

The public URL is specific to this owner's deployment. A clone of the repository needs its own Cloudflare configuration. Runtime ports, PostgreSQL and the owner API are not publicly exposed. LAN HTTPS is implemented as an optional separate listener but is not configured on this host; the protected public URL works for browser users on the LAN too.

## Included changes

| Area | Behavior |
| --- | --- |
| Private accounts | Conversations and tasks are isolated by account; pending/disabled users, revocation, provider grants and budgets are enforced at the host. |
| Private files | Approved users can create their own managed workspace, upload/edit/download/delete bounded text files, and choose read-only, supervised or autonomous access there. Shared host folders retain separate owner grants. |
| Host-file mode | Local-owner confirmation switches from the managed-copy scope to direct host files. This avoids loading two file-tool catalogs implicitly and exhausting the default context. A managed workspace can be selected again explicitly. Protected paths and isolated-command requirements remain enforced. |
| Attachments | Paperclip or drag-and-drop uploads. PDF and modern Word DOCX import a bounded text copy through an isolated parser process; originals are unchanged. Unsupported OCR, encrypted documents and legacy DOC are identified explicitly. |
| Device folders | Supported desktop browsers can read a chosen folder, preview an uploaded copy, and apply selected host changes back with explicit write permission and conflict checks. Phone/unsupported browsers retain upload/download. |
| Specialists | Ten role profiles use shared orchestration, model routing and policy. File-capable agent setup creates a private workspace when needed. Missing Gmail, Calendar, browser/desktop connectors are clearly identified instead of implying that no file tools exist. |
| Model discovery | Opening Models fetches actual installed local models from Ollama/LM Studio. Refreshes are coalesced and authenticated; the installed list is not hard-coded. |
| Routing | Hardware, user policy, tools, context, availability and cloud egress remain hard eligibility checks. Specialist/keyword task categories and optional artifact-bound fixed probes add disclosed evidence to ranking. A tiny probe is not a broad intelligence guarantee. |
| Visible model | Auto and specialist tasks show actual model-selection/call records, including fallback changes and persisted completed assignments. |
| Memory protection | Agent and external-client requests recheck admission after waiting, then sample free RAM/VRAM and swap during generation. Unsafe pressure cancels and pauses without automatic rerouting. Multi-GPU admission is conservative when the runtime cannot pin a device. Sampling and cancellation cannot guarantee against sudden driver/OS failures. |
| Completion alerts | Tracked successful tasks produce in-app alerts. Optional browser notifications require explicit permission and use generic content while the tab is in the background. Historical events do not create duplicate alerts; unsupported mobile browsers fall back to in-app messages. |
| Token policy | Efficient/Standard and per-call output allowances share one context/request/cost policy. Required evidence stays intact; partial tool output is rejected and truncation pauses. No claim of measured percentage savings. |
| Providers | Optional OpenAI, Anthropic, Gemini, xAI/Grok and DeepSeek adapters, private per-user credentials, usage and last-observed rate limits where exposed. No invented remaining subscription balance. |
| Google connection | Gemini OAuth with one-time owner configuration, PKCE, signed identity verification, per-user OS-vault refresh tokens and a disclosed quota project. Real app registration/consent is still needed. It does not unlock other companies' consumer subscriptions. |
| External clients | Revocable account tokens expose bounded local inference without storing their conversation content. Tool proposals execute on the client's computer. Complete Codex/Claude Code compatibility is not certified. |

## What remains to reach the full product vision

1. **Real connected agents:** Gmail/Calendar scopes, consent, rate limits and action approvals; browser automation and native desktop connectors. Current role profiles do not perform these unavailable external actions.
2. **Provider setup and live acceptance:** configure the owner's Google application and verify actual consent/model quota; exercise every configured cloud provider. OpenAI consumer sign-in requires its own supported adapter and shared-host eligibility review. There is no generic Google sign-in that grants Claude, Grok or DeepSeek API access.
3. **Cross-platform release validation:** rerun current code on native Linux and macOS, Apple Silicon/AMD/Intel/CPU-only hardware, real Docker and native PostgreSQL. Sign/package native installers, configure background services and secure updates. Existing older Ubuntu WSL evidence is not acceptance of every new feature.
4. **Deployment operations:** install a managed tunnel service, validate outage/reconnect/revocation on physical devices, and configure trusted LAN TLS if offline LAN access is desired. Public external inference needs a separately reviewed gateway; the browser Worker denies it.
5. **Broader model evaluations:** held-out multilingual coding/reasoning/tool tasks, actual executable verification, per-hardware/context configuration, repeated measurements and honest quality/latency comparisons before adopting a learned router. Researched libraries are not better merely because they exist.
6. **Notifications beyond an open browser:** secure push delivery, service-worker lifecycle, device enrollment/revocation and privacy controls. Scheduled reminders are distinct from task-completion alerts.
7. **Operations and security hardening:** independent audit, backup/restore drills, storage retention/quotas for database and logs, hostile same-user threat model, dependency/update review and physical accessibility/screen-reader checks.
