# Semantic routing comparison v1

Sixteen advisory categories. No classifier may authorize a tool, external request, cloud spend or model load. Unknown downstream model quality remains unknown.

Training: prior `benchmarks/task-intent/development-v1.json` is reused explicitly as route examples. It is **training**, never semantic validation. Development: new `development-v1.json`, 32 implementer-authored EN/HE objectives. Held-out: independent reviewer authors 64 new EN/HE objectives without reading either corpus, adapters or scores. Root does not inspect objectives until after code/threshold/evaluator/model freeze. Cases use required and forbidden labels, so exact-match accuracy, precision and F1 would be misleading. Report satisfied constraints, missed required labels and forbidden predictions, separately by language.

Three real CPU candidates: Semantic Router with multilingual MiniLM, the same library with multilingual E5-small, and Transformers zero-shot multilingual MiniLM NLI. Static route example matching uses library maximum aggregation and multi-route results. No model training or handcrafted keyword changes. NLI uses fixed label descriptions. Development chooses a global threshold from 0.10–0.95 in 0.05 increments, maximizing satisfied cases, then reducing forbidden/missing labels. Select the candidate on development only; test performance cannot trigger selection of a different candidate.

Promotion gates declared before held-out execution: at least 8 more satisfied cases than the frozen phrase baseline out of 64; neither language may regress; forbidden predictions may not exceed baseline by more than two; p95 warm classification below 250ms; process RSS below 1.5GiB; initialization below 30 seconds. Those are minimum experiment gates, not proof of general understanding. Refuse promotion if any fails. Timing uses sequential two-thread CPU processes with no competing test/inference workload. Each process records actual initialization, RSS and warm case latencies. VRAM is zero by configured CPU execution, not a sampled GPU allocation claim. Download time is separate.

Before test: write an exclusive manifest binding this protocol, candidate adapters, evaluator, baseline and training/development/test file hashes, package versions, model revisions and selected thresholds. Test never tunes. Any later adjustment requires a new test corpus for an unseen claim. Retain all candidates, failures and integration limits. The existing phrase heldout set remains historical; it is not reused as fresh unseen evidence.

Downstream eligibility tests and real end-to-end outcomes are separate. Passing these minimum intent gates is insufficient to declare the overall routing replacement or platform complete. Cross-platform latency, calibration under contention, long-input recall, and physical mobile/live-account tests remain required.
