# Public research and managed Git inspection

Relay exposes `http_get`, `git_status` and `git_diff` as structured broker tools. The orchestrator persists the request, deterministic decision, result and factual evidence through the same tool-call/audit path as filesystem tools. Returned content is untrusted data; it cannot alter capabilities. These tools do not perform browser automation, general shell execution, Git commits, source-repository mutations or authenticated web sessions.

## Network authority

Task network policy is independent from filesystem access and cloud-model egress. Its modes are `deny`, `ask` and `allow`, with at most 16 exact public HTTPS origins. Deny is the default. An `ask` request needs exact-action approval; `allow` grants requests only to the listed origins. Reading a webpage does not require a managed workspace. The controller still checks the requesting user and agent capabilities; a model cannot supply policy fields in tool arguments.

`server/tools/network-policy.ts` validates and canonicalizes origins. Credential-bearing URLs, fragments, non-443 ports, private/literal special addresses, control characters, local hostnames, oversized queries and common credential query keys/token formats are rejected before DNS. `safeHttpRequestForRecord` replaces rejected URLs with a denial marker before persistence. The URL leak check is deliberately conservative but is **not general DLP**: an authorized origin can receive the path/query the agent requests, including arbitrary ordinary text. Owners should grant only destinations appropriate for that task's information.

`server/tools/http.ts` resolves all DNS answers and rejects mixed public/private answers. It pins a checked address through Node's connection lookup, retains the original TLS hostname, explicitly requires certificate verification, disables shared agents, and checks the connected address. It never adds cookies, authorization, arbitrary headers, a request body or environment proxy configuration. Up to three redirects are revalidated against the origin grant and freshly resolved/pinned. The request has a ten-second total deadline, 8 KiB response-header limit, 512 KiB transfer limit, and 16 KiB text output limit. Only UTF-8/ASCII text, HTML, Markdown, JSON and XHTML are accepted. Compressed responses are rejected. Oversized transfer is an error; truncated output is explicitly marked. SHA-256 covers the received response bytes. HTTP error statuses are observations, not fabricated successful research conclusions.

Task cancellation and emergency stop abort live requests. Aborted DNS work may finish in the operating system, but cannot start a later request. Tests inject DNS/transport responses to exercise rebinding, redirect, output, cancellation and egress boundaries. A live request to official Node.js HTTPS documentation returned HTTP 200 and 162,278 bytes through this client; output truncation was reported. This verifies the native network path, not every remote site or operating system.

This design follows the [OWASP SSRF prevention guidance](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html), [Node HTTPS request contract](https://nodejs.org/api/https.html), and [Node address blocklists](https://nodejs.org/api/net.html#class-netblocklist). Conservative exclusions use the [IANA IPv4](https://www.iana.org/assignments/iana-ipv4-special-registry) and [IPv6 special-purpose registries](https://www.iana.org/assignments/iana-ipv6-special-registry). Address policy intentionally denies some special-purpose globally reachable services rather than trusting all globally formatted addresses.

## Actual Git, intentionally scoped

Relay never imports the source `.git` directory. Consequently `git_status` cannot honestly claim source branch/index/untracked/ignore semantics. It uses the installed Git executable to compare the **managed text snapshot** with a Relay baseline:

- New workspaces capture their permitted source files at workspace creation. Later uploads are changes against that baseline.
- Legacy workspaces capture their first Git inspection as `first_inspection`, with a timestamp. The response discloses this; previous import state is not invented.
- Baselines persist beneath the host data directory, separately from agent-accessible files, and share the workspace's 2,000-file/50-MiB limits.
- Each inspection makes a temporary bare SHA-256 Git repository. The baseline and current snapshot enter it through fixed `fast-import` commands with byte-counted inline blobs. Actual Git `diff-tree` produces status or unified diffs. Files never pass through repository filters. Temporary object storage is removed after the child exits.

Git discovery uses standard OS installation paths, never a model-selected executable or workspace PATH. Child processes use argument arrays without a shell, a private working directory, a restricted environment, disabled system/global config, zero inherited `GIT_CONFIG_*` entries, an empty template/attributes/hooks directory, no external diff/textconv helpers, disabled fsmonitor and credential helpers, and no transport protocols. Raw `.gitattributes` files are snapshot content, not execution authority. Commands have a 30-second total inspection budget, bounded stdout/stderr, and task/global cancellation. A fixed Git process is not presented as native isolation for arbitrary host commands.

`git_status` reports additions, modifications and deletions without rename inference. Both tools return baseline provenance and explicit truncation. Real Git integration tests cover non-ASCII paths, source preservation, malicious inherited configuration/helper settings, legacy baseline recovery and large output. Windows validation uses installed Git 2.52.0; Git with SHA-256 repository support is required. Standard-path discovery supports Windows, Linux and macOS, but a platform requires native validation before claiming support guarantees.

The implementation uses documented [Git configuration controls](https://git-scm.com/docs/git-config), [hook behavior](https://git-scm.com/docs/githooks), the byte-counted [fast-import protocol](https://git-scm.com/docs/git-fast-import), and [diff-tree options](https://git-scm.com/docs/git-diff-tree). The boundary does not protect against an already-compromised same-OS account replacing the trusted Git installation or host data; that remains outside the managed-workspace threat model.
